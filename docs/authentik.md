# Authentik

OIDC sign-in for the cluster's own apps, at `https://auth.home.jakehulberg.com`. Infisical keeps its
own login.

## What's in `apps/authentik/`

| File | What |
|---|---|
| `postgres.yaml` | Namespace `authentik`, CloudNativePG `Cluster` `authentik-db` (1 instance, 2Gi, no backups yet) |
| `secrets-sync.yaml` | Syncs `/authentik` from Infisical Cloud (`AUTHENTIK_SECRET_KEY`) into `authentik-secrets-infisical` |
| `authentik.yaml` | `HelmRepository` and `HelmRelease` (chart `authentik` `2026.8.5`) |
| `httproute.yaml` | `auth.home.jakehulberg.com` → Service `authentik-server` port 80 |

## How it's wired

```
auth.home.jakehulberg.com → Traefik → HTTPRoute → Service authentik-server:80 → server pod
server and worker pods:
  AUTHENTIK_SECRET_KEY        ← Secret authentik-secrets-infisical (synced from Infisical Cloud)
  AUTHENTIK_POSTGRESQL__*     → authentik-db-rw, database and user "authentik"
  AUTHENTIK_POSTGRESQL__PASSWORD ← Secret authentik-db-app, key password (generated by CloudNativePG)
```

No Redis: Authentik dropped it, and the chart has no Redis settings.

## Chart values, and why

| Value | Why |
|---|---|
| `authentik.existingSecret.secretName: authentik-secrets-infisical` | The chart reads its settings from the synced Secret instead of creating its own. Setting `secret_key` in values instead would put it in git. |
| `global.env` `AUTHENTIK_POSTGRESQL__*` | Points both server and worker at CloudNativePG. The bundled Postgres (`postgresql.enabled`) is off by default. |

`AUTHENTIK_SECRET_KEY` signs cookies and user IDs. Never change it after the first install. To
generate one: `openssl rand -base64 60 | tr -d '\n'`.

## First boot

The server and worker sit at `0/1 Running` for a few minutes while they wait for the database and
run migrations.

**Then create the admin account immediately** at `https://auth.home.jakehulberg.com/if/flow/initial-setup/`.
Until then, anyone on the tailnet can claim it.

Keep the admin login in a password manager, not in the `homelab` Infisical project: everything there
is readable by the cluster's machine identity, and `/authentik` is loaded into the pods' environment.

## Adding an app (OIDC)

In the admin UI: **Applications → Applications → Create with provider**.

| Setting | Value |
|---|---|
| Name, slug | App name; the slug becomes part of the issuer URL |
| Group, policy engine mode | Empty, `any` |
| Provider type | OAuth2/OpenID Connect |
| Authorization flow | `default-provider-authorization-implicit-consent` (no "allow?" screen) |
| Invalidation flow | `default-provider-invalidation-flow` |
| Client type | Confidential |
| Redirect URIs | Strict, the app's callback URL, once |
| Signing key | `authentik Self-signed Certificate`. Empty means HS256, which most OIDC libraries reject. |
| Scopes | Defaults (openid, email, profile) |
| Subject mode | Default (hashed user ID). Don't change it later; apps key users on it. |
| Include claims in id_token | On |
| Issuer mode | Default (per provider) |
| Bindings | None: anyone who can sign in to Authentik can use the app |

The issuer URL is `https://auth.home.jakehulberg.com/application/o/<slug>/`. Put it, the client ID
and the client secret in the app's Infisical folder.

| App | Slug | Redirect URI |
|---|---|---|
| Airlock | `airlock` | `https://airlock.home.jakehulberg.com/callback` ([airlock](airlock.md)) |
