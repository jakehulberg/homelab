# Authentik

Authentik is the OIDC sign-in for the cluster's own apps, at `https://auth.home.jakehulberg.com`.
[Airlock](airlock.md) signs users in through it. Infisical keeps its own login.

## How it fits together

```
auth.home.jakehulberg.com ──▶ Traefik ──HTTPRoute──▶ Service authentik-server:80 ──▶ server pod

server and worker pods:
  AUTHENTIK_SECRET_KEY            ◀── Secret authentik-secrets-infisical (from Infisical Cloud)
  AUTHENTIK_POSTGRESQL__*         ──▶ authentik-db-rw, database and user authentik
  AUTHENTIK_POSTGRESQL__PASSWORD  ◀── Secret authentik-db-app, key password (from CloudNativePG)
```

Authentik no longer uses Redis, and the chart has no Redis settings.

## What's where

| Path | What |
|---|---|
| `apps/authentik/postgres.yaml` | Namespace `authentik`, CloudNativePG `Cluster` `authentik-db` (1 instance, 2Gi, WAL archived to R2) |
| `apps/authentik/secrets-sync.yaml` | Syncs `/authentik` from Infisical Cloud (`AUTHENTIK_SECRET_KEY`) into `authentik-secrets-infisical` |
| `apps/authentik/authentik.yaml` | `HelmRepository` and `HelmRelease` (chart `authentik` `2026.8.5`) |
| `apps/authentik/httproute.yaml` | `auth.home.jakehulberg.com` → Service `authentik-server` port 80 |
| `apps/authentik/objectstore.yaml`, `scheduled-backup.yaml`, `r2-sync.yaml` | Backups to R2 ([Backups](#backups)) |
| Infisical Cloud | `/authentik` and `/r2` |
| Authentik's database | Admin account, applications and providers, set in the admin UI |

## Secrets

| Secret | What | Used by |
|---|---|---|
| `AUTHENTIK_SECRET_KEY` | In `/authentik`. Signs cookies and user IDs. `openssl rand -base64 60 \| tr -d '\n'` | server, worker |
| `authentik-db-app` | Database password, generated by CloudNativePG | server, worker |
| `r2-credentials-authentik` | R2 keys, from `/r2` | `authentik-db` backups |

Never change `AUTHENTIK_SECRET_KEY` after the first install.

## Chart values, and why

| Value | Why |
|---|---|
| `authentik.existingSecret.secretName: authentik-secrets-infisical` | The chart reads its settings from the synced Secret instead of creating its own. Setting `secret_key` in values instead would put it in git |
| `global.env` `AUTHENTIK_POSTGRESQL__*` | Points both server and worker at CloudNativePG. The bundled Postgres (`postgresql.enabled`) is off by default |

## Backups

`authentik-db` streams its WAL to R2 and takes a daily base backup at 03:00, kept for 30 days,
the same way as `infisical-db` ([storage](storage.md#databases)).

## First boot

The server and worker show `0/1 Running` for a few minutes while the database starts and the
migrations run.

**Then create the admin account immediately** at
`https://auth.home.jakehulberg.com/if/flow/initial-setup/`. Until the admin account exists,
anyone on the tailnet can claim it.

Keep the admin login in a password manager, not in the `homelab` Infisical project. The cluster's
machine identity can read everything in that project, and `/authentik` is loaded into the pods'
environment.

## Adding an app (OIDC)

1. In the admin UI, select **Applications → Applications → Create with provider**
2. Fill in the settings below
3. Put the issuer URL, `https://auth.home.jakehulberg.com/application/o/<slug>/`, the client ID
   and the client secret in the app's Infisical folder

| Setting | Value |
|---|---|
| Name, slug | App name; the slug becomes part of the issuer URL |
| Group, policy engine mode | Empty, `any` |
| Provider type | OAuth2/OpenID Connect |
| Authorization flow | `default-provider-authorization-implicit-consent` (no "allow?" screen) |
| Invalidation flow | `default-provider-invalidation-flow` |
| Client type | Confidential |
| Redirect URIs | Strict, the app's callback URL, once |
| Signing key | `authentik Self-signed Certificate`. If it's empty, Authentik signs with HS256, which most OIDC libraries reject |
| Scopes | Defaults (openid, email, profile) |
| Subject mode | Default (hashed user ID). Don't change it later; apps key users on it |
| Include claims in id_token | On |
| Issuer mode | Default (per provider) |
| Bindings | None: anyone who can sign in to Authentik can use the app |

| App | Slug | Redirect URI |
|---|---|---|
| Airlock | `airlock` | `https://airlock.home.jakehulberg.com/callback` ([airlock](airlock.md)) |

## Checking it

```sh
kubectl get pods -n authentik              # server, worker and authentik-db-1 Running
kubectl get cluster authentik-db -n authentik  # Cluster in healthy state
kubectl get helmrelease authentik -n authentik # Ready True
```
