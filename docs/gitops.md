# GitOps

Flux applies this repo to the cluster, so you change the cluster by pushing to `main`. Flux checks
GitHub for new commits every minute and applies them.

## How Flux reads the repo

```
clusters/homelab/
  flux-system/                  Flux itself (generated by bootstrap, don't edit)
  infrastructure.yaml           applies ./infrastructure/controllers
  infra-configs.yaml            applies ./infrastructure/configs, once infrastructure is Ready
  apps.yaml                     applies ./apps, once infra-configs is Ready
  image-update-automation.yaml  commits image tag bumps under ./apps back to main

infrastructure/
  controllers/          Helm charts and CRDs: Gateway API, Traefik, cert-manager, CloudNativePG,
                        Infisical Operator, agent-sandbox, Prometheus Operator CRDs, experiments
    kustomization.yaml  which subfolders to include
    <component>/
      kustomization.yaml  which files in this folder to include
      ...
  configs/              objects of those types: Let's Encrypt issuer, certificate, Infisical Cloud
                        connection and operator login, Cloudflare token sync
    kustomization.yaml
    ...

apps/                   podinfo, infisical, life-dashboard, authentik, agents, airlock,
                        agent-vault, monitoring, experiments
  kustomization.yaml    which app folders to include
  podinfo/
    kustomization.yaml
    podinfo.yaml
    httproute.yaml
```

Flux reads only `clusters/homelab/` and what it points at. It ignores `lima/`, `k3s/` and `docs/`.

## Apply order

Three Flux Kustomizations apply the repo, each waiting for the one before it:

```
flux-system ──(1)──▶ infrastructure ──(2)──▶ infra-configs ──(3)──▶ apps
                     (controllers)           (configs)
```

1. The root Kustomization (`flux-system`, in `gotk-sync.yaml`) applies `clusters/homelab/`,
   including the three Kustomizations
2. `infrastructure` applies `./infrastructure/controllers`. With `wait: true`, `infrastructure`
   isn't Ready until everything it applied is healthy
3. `infra-configs` (`dependsOn: infrastructure`, `wait: true`) applies `./infrastructure/configs`,
   then `apps` (`dependsOn: infra-configs`) applies `./apps`

In each folder, Flux applies only the files listed in `resources` of its `kustomization.yaml`.

### Why controllers and configs are split

Configs use types the controllers install (a ClusterIssuer is a cert-manager type). Flux validates
every file in a Kustomization before it applies any of them, so on a fresh cluster a ClusterIssuer
next to cert-manager fails with "no matches for kind". A second Kustomization that waits for the
first avoids that error. The layout follows Flux's `fluxcd/flux2-kustomize-helm-example`:

- Helm charts and CRDs go in `infrastructure/controllers/`
- Objects of those types go in `infrastructure/configs/`

The first Kustomization is named `infrastructure`, not `infra-controllers` as in the example.
Don't rename it: renaming a Flux Kustomization deletes and reinstalls everything it manages.

## Two things called Kustomization

| | Kustomize | Flux |
|---|---|---|
| File | `kustomization.yaml` in every folder | `infrastructure.yaml`, `infra-configs.yaml`, `apps.yaml` |
| `apiVersion` | `kustomize.config.k8s.io/v1beta1` | `kustomize.toolkit.fluxcd.io/v1` |
| Says | which files belong to this folder | apply this folder, how often, in what order |

## Add an app

1. Create `apps/<name>/` with its YAML and a `kustomization.yaml` that lists the files
2. Add `- <name>` to `apps/kustomization.yaml`
3. Commit and push

Infrastructure works the same way, under `infrastructure/controllers/` or
`infrastructure/configs/`.

## Remove an app

Delete its line from `apps/kustomization.yaml` and push. With `prune: true`, Flux deletes
everything it created for the app. The folder can stay.

## Helm charts from OCI registries

An `OCIRepository` source (`oci://...`) needs a `layerSelector`. Some artifacts (Traefik's) carry
extra layers, like a signature. Without a `layerSelector`, Flux unpacks the wrong layer and fails
with `gzip: invalid header`.

```yaml
apiVersion: source.toolkit.fluxcd.io/v1
kind: OCIRepository
spec:
  url: oci://ghcr.io/<org>/<chart>
  ref:
    tag: "<exact version>"
  layerSelector:
    mediaType: "application/vnd.cncf.helm.chart.content.v1.tar+gzip"
    operation: copy
```

Configure a chart through its HelmRelease `values`, not by copying the chart. To see every setting
and its default:

```sh
helm show values oci://ghcr.io/<org>/<chart> --version <version>
```

## Checking it

```sh
flux get kustomizations                           # all Ready True
flux reconcile kustomization apps --with-source   # apply the latest push to apps now
```

## Troubleshooting

- **Pushed a file, and `kubectl get` says `No resources found`:** the file isn't listed in its
  folder's `kustomization.yaml`
- **Stuck on `Reconciliation in progress`:** `infrastructure` and `infra-configs` wait up to 10
  minutes for everything they applied to be healthy, and hold new pushes until then. Find what's
  unhealthy with `flux get helmreleases -A` or `kubectl get certificate -A`
- **`dependency '...' is not ready`:** fix the Kustomization earlier in the chain; the later ones
  apply once it's Ready
