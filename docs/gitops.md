# GitOps

The cluster is changed by pushing to `main`. Flux checks GitHub every minute and makes the cluster
match the repo.

## How Flux reads the repo

```
clusters/homelab/
  flux-system/          Flux itself (generated by bootstrap, don't edit)
  infrastructure.yaml   "apply ./infrastructure"
  apps.yaml             "apply ./apps, once infrastructure is healthy"

infrastructure/         things everything else needs: Traefik, cert-manager, storage
  kustomization.yaml    table of contents: which subfolders to include
  <component>/
    kustomization.yaml  which files in this folder to include
    ...

apps/                   things you use: podinfo, Infisical, draw.io
  kustomization.yaml
  podinfo/
    kustomization.yaml
    podinfo.yaml
```

1. Flux's root Kustomization (`flux-system`, in `clusters/homelab/flux-system/gotk-sync.yaml`)
   applies everything in `clusters/homelab/`. That includes the two pointers.
2. `infrastructure.yaml` applies `./infrastructure`. `wait: true` means it's only `Ready` once
   everything in it is healthy.
3. `apps.yaml` applies `./apps`, with `dependsOn: infrastructure`, so apps never come up before
   the things they need.
4. In each folder, Flux follows `kustomization.yaml`'s `resources` list. Anything not listed is
   ignored.

Only `clusters/homelab/` and the folders it points at are read. `lima/`, `k3s/` and `docs/` are
ignored by Flux.

## Two things called Kustomization

| | Kustomize | Flux |
|---|---|---|
| File | `kustomization.yaml` in every folder | `infrastructure.yaml`, `apps.yaml` |
| `apiVersion` | `kustomize.config.k8s.io/v1beta1` | `kustomize.toolkit.fluxcd.io/v1` |
| Says | which files belong to this folder | apply this folder, how often, in what order |

## Add an app

1. Make `apps/<name>/` with the app's YAML and a `kustomization.yaml` listing those files.
2. Add `- <name>` to `apps/kustomization.yaml`.
3. Commit and push.

Infrastructure works the same way under `infrastructure/`.

## Remove an app

Delete its line from `apps/kustomization.yaml` and push. `prune: true` makes Flux delete everything
it created. The folder can stay in the repo for later.

## Helm charts from OCI registries

Charts pulled with an `OCIRepository` (`oci://...`) need a `layerSelector`. Some chart artifacts
(Traefik's, for one) carry extra layers like signatures, and without it Flux tries to unpack the
wrong one and fails with `gzip: invalid header`.

```yaml
apiVersion: source.toolkit.fluxcd.io/v1
kind: OCIRepository
spec:
  url: oci://ghcr.io/<org>/<chart>
  ref:
    tag: "<exact version>"
  layerSelector:
    mediaType: "application/vnd.cncf.helm.chart.content.v1.tar+gzip"
    operation: copy
```

Change chart settings with `values` in the HelmRelease, not by copying the chart. To see every
setting and its default: `helm show values oci://ghcr.io/<org>/<chart> --version <version>`.

## Troubleshooting

- **Pushed a file, `kubectl get` says `No resources found`:** the file isn't listed in its folder's
  `kustomization.yaml`.
- **A Kustomization is stuck on `Reconciliation in progress`:** `infrastructure` has `wait: true`,
  so it waits on every HelmRelease in it. `flux get helmreleases -A` shows which one, and its
  message says why.
- **`apps` says `dependency 'flux-system/infrastructure' is not ready`:** fix `infrastructure`
  first; `apps` follows.

## Apply now instead of waiting

```sh
flux reconcile kustomization apps --with-source
```
