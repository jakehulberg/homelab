# Infisical

The cluster's own Infisical: a fresh stock install at `https://infisical.home.jakehulberg.com`.
Its settings and keys come from Infisical Cloud ([secrets](secrets.md)), and its database runs on
CloudNativePG ([storage](storage.md)).

The demo instance (dummy data for videos) runs separately in Docker on mini3, outside this repo.

## What's where

| File (`apps/infisical/`) | What |
|---|---|
| `postgres.yaml` | Namespace `infisical`, CloudNativePG `Cluster` `infisical-db` (2 instances, 5Gi) |
| `redis.yaml` | Own Redis (`redis:8.10-alpine`): password required, no persistence (Infisical uses it only as cache and queue) |
| `infisical-secrets-sync.yaml` | Syncs `/infisical` from Infisical Cloud (`ENCRYPTION_KEY`, `AUTH_SECRET`, `REDIS_PASSWORD`, `REDIS_URL`, `SITE_URL`) into `infisical-secrets-infisical` ([secrets](secrets.md#infisicals-own-keys)) |
| `infisical.yaml` | `HelmRepository` and `HelmRelease` (chart `infisical-standalone` `1.12.0`, image `infisical/infisical:v0.167.4`) |
| `httproute.yaml` | `infisical.home.jakehulberg.com` to Service `infisical` port 8080 |
| `r2-sync.yaml`, `objectstore.yaml`, `scheduled-backup.yaml` | Database backups to R2 ([storage](storage.md#backups)) |

## How it fits together

```
infisical.home.jakehulberg.com ──▶ Traefik ──HTTPRoute──▶ Service infisical:8080 ──▶ Infisical pod

Infisical pod
  DB_CONNECTION_URI  ◀── Secret infisical-db-app, key uri    (generated by CloudNativePG)
  everything else    ◀── Secret infisical-secrets-infisical  (synced from Infisical Cloud)
  REDIS_URL          ──▶ redis://:<password>@redis:6379      (Service redis, same namespace)
```

`REDIS_URL` uses the short Service name `redis`, not `redis.infisical.svc.cluster.local`
([Troubleshooting](#troubleshooting)).

## Chart values, and why

The chart bundles Postgres, Redis and ingress-nginx sub-charts, all on by default (see
`dependencies` in `helm show chart infisical-helm-charts/infisical-standalone --version 1.12.0`).
All three are off:

| Value | Why |
|---|---|
| `postgresql.enabled: false` + `useExistingPostgresSecret` to `infisical-db-app` / `uri` | CloudNativePG instead (replicated, backed up). The bundled one uses unmaintained `bitnamilegacy` images and password `root` |
| `redis.enabled: false` | Same image problem, and its password (default `mysecretpassword`) would sit in plain text here. `REDIS_URL` comes from the synced Secret |
| `ingress.enabled: false` and `ingress.nginx.enabled: false` | Traefik is the front door. ingress-nginx has its own switch; `ingress.enabled` alone still installs it |
| `infisical.replicaCount: 1` | The chart's default is 2 at up to 1GB each. One is plenty |
| `infisical.image.tag` | Pinned so Renovate bumps the app, not just the chart |
| `infisical.fullnameOverride: infisical` | Otherwise the Service is `infisical-infisical-standalone-infisical`. The HTTPRoute targets `infisical` |
| `infisical.kubeSecretRef: infisical-secrets-infisical` | Infisical's settings Secret, synced by the operator. Redis reads `REDIS_PASSWORD` from it too |

To preview what the chart creates, without touching the cluster:

```sh
helm repo add infisical-helm-charts 'https://dl.cloudsmith.io/public/infisical/helm-charts/helm/charts/'
helm template infisical infisical-helm-charts/infisical-standalone --version 1.12.0 -n infisical \
  --set infisical.replicaCount=1,infisical.fullnameOverride=infisical,postgresql.enabled=false,redis.enabled=false,ingress.enabled=false,ingress.nginx.enabled=false \
  | grep -E '^kind:|^  name:'   # Deployment, Service, ServiceAccount, Role, RoleBinding; no NGINX, Postgres or Redis
```

## First boot

On a fresh database, the first start takes about 10 minutes: Infisical replays every migration
since its first release, and if the pod and the primary are on different nodes, each query crosses
Tailscale over Wi-Fi. The pod stays at `0/1 Running` until the migrations finish. Later restarts
take seconds, and upgrades run only the new migrations.

```sh
kubectl get pods -n infisical -w                    # 1/1, RESTARTS 0
kubectl logs -n infisical deploy/infisical -f       # migration steps
```

**Create the admin account immediately.** Until then, anyone on the tailnet can claim the
instance.

## Upgrading

Renovate opens separate PRs for the chart `version` and for `infisical.image.tag` in the
HelmRelease ([updates](updates.md)). Before merging a chart bump, check the release notes and
diff `helm show values` on the new version for value changes.

## Backups

The database backs up continuously to R2, plus a daily full backup
([storage](storage.md#backups)). A restored database is unreadable without `ENCRYPTION_KEY` and
`AUTH_SECRET` from Infisical Cloud ([secrets](secrets.md#infisicals-own-keys)).

## Troubleshooting

- **`RESTARTS` above 0 during first boot:** Kubernetes killed the pod mid-migration. Give the pod
  a longer startup allowance
- **Pod stuck at `0/1` with `Redis connection error ... ETIMEDOUT` from `[client=bootstrap]`:**
  Infisical's startup Redis check timed out on a slow DNS lookup. Check that `REDIS_URL` uses the
  short name `redis` and that the cluster DNS fix is in place
  ([networking](networking.md#dns-inside-the-cluster))
